AI-assisted development standards

How EML students use Cursor, GitHub, Trello, and Harvest — without losing quality, context, or the next cohort.

Onboarding briefing · eml.ubc.ca

Why this exists

Students rotate twice a year. Projects do not.

  • We hire new students each term across web, Unity, and Unreal — sometimes VR.
  • AI coding is strongest on web, usable in Unity C#, and weak in Unreal Blueprints.
  • Without shared rules, each cohort invents process — and the next one inherits folklore.
  • These standards keep work reviewable, searchable, and handoff-ready.

Five principles

How we work with AI

01

AI assists; humans own decisions

You are accountable for architecture, merges, and shipped behavior.

02

Search before you dump files

Use tree-sitter MCP for navigation. Read only the ranges you need.

03

Docs are a handoff artifact

Every project must survive a semester turnover without oral tradition.

04

Platform realism

Mandate AI where it works. Constrain it where it fails — especially Blueprints.

05

One system of record per concern

Trello for planning. GitHub for code. Harvest for time. Link them — do not duplicate.

Category 1–2

Cursor + tree-sitter MCP

  • Every repo ships .cursor/mcp.json and search rules.
  • Agents must query symbols before reading whole files.
  • Saves tokens, reduces shallow edits, keeps context small.
  • Needs Python 3.11+ and uv. MCP must show green in Cursor.

Lab-standard server

codetree — local AST index, no vector DB.

Web: TS/JS · Unity: C# · Unreal: C/C++ headers and sources.

Never dump node_modules, Unity Library/, or Unreal binaries into chat.

Token discipline

Keep sessions small and honest

  • Use Ask / Plan to explore. Use Agent for one feature or bug at a time.
  • Never commit AI output without reading the diff.
  • Disclose AI use on every PR. Reviewers check behavior, not just green CI.
  • Run /review-eml before opening a pull request.

Category 3

Source control is non-negotiable

Protected main

No direct pushes. PR + ≥1 approval. Branch deleted after merge.

Branch names

feat/* · fix/* · docs/* — docs PRs are the first-week exercise.

Conventional commits

feat(web): …
fix(unity): …
docs: …

Web: no binaries > 1 MB. Unity/Unreal: Git LFS for assets. Never commit secrets.

Category 4

Four documents every repo needs

README.md

Setup, run, test, deploy in ≤10 commands. Contact + layout.

docs/architecture.md

Components, data flow, external services, tech debt.

docs/setup.md

Tool versions, env vars, MCP troubleshooting, hardware.

docs/handoff.md

Updated every semester: what works, WIP, gotchas, next priorities.

Category 5

Quality is platform-specific

Web

Full CI gate

ESLint, Prettier, TypeScript strict, tests, GitHub Actions on every PR.

Unity

C# + screenshots

Analyzers and Edit Mode tests. No AI-edited YAML. Scene PRs need a screenshot.

Unreal

Human-heavy review

clang-format for C++. Blueprint changes require exported docs.

Category 6

A 12-week semester rhythm

WeeksFocus
1–2Onboarding, MCP green, docs-only first PR, Trello + Harvest access
3–10Feature work. Weekly 3-bullet status on the Trello card: done / doing / blocked
11–12Handoff doc, tagged demo release, Harvest export, retrospective

No single hero owner. Returning students mentor the first two weeks.

Categories 8–9

Trello plans. Harvest times.

Trello — one board per codename

Backlog → Ready → In Progress → In Review → Done → Handoff notes

Code cards need a GitHub issue before In Progress. Tag this-term vs future.

Harvest — same codename

Log daily. Start the timer from the Trello card.

Dev notes must include the issue number. Use the AI-assisted dev task when you used Cursor.

Integration

One feature, end to end

Trello Ready→ GitHub issue→ Harvest timer→ Cursor + MCP→ PR / review→ Merge→ Close issue→ Trello Done
  • No orphan PRs. No orphan issues. No untracked dev time.
  • Detailed spec lives in GitHub. Trello holds a summary plus a link.
  • non-code work (equipment, admin) skips GitHub — still log Harvest.

Category 7

Security has no exceptions

  • Secrets never live in git. .env.example only. Use 1Password or GitHub Secrets.
  • No student records or confidential research pasted into public models.
  • Follow UBC IT policy. Track Unity / Unreal / OSS licenses.
  • Secret scanning (gitleaks) on org repos.

Getting started

Week 1 checklist

Access

GitHub org, Trello board, Harvest project, Cursor license.

MCP

Install uv. Open the repo. Confirm codetree is green.

Clone & run

Follow README. First merge is a docs-only PR within a week.

Time

Log your first Harvest entry from a Trello card.

Template

New web repos start from the GitHub template

  • template/ includes .cursor/, MCP, PR/issue forms, docs, and CI stubs.
  • Use this template → name the repo with the project codename.
  • Replace placeholders, add Trello + Harvest URLs, enable branch protection.
  • Full write-up lives in PLAN.md in the standards repo.

Remember

If you only keep five rules

  • Search with MCP. Don’t paste the whole repo into chat.
  • Protected main, reviewed PRs, conventional commits.
  • README, architecture, and a semester handoff — always.
  • Trello · GitHub · Harvest stay linked. Codename is the same everywhere.
  • Web: full AI. Unity: C# only. Unreal: C++ help; Blueprints are yours.
